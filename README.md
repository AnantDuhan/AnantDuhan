### 🏛️ [MAISON](https://maisonorderplanning.in) — a luxury e-commerce platform, on web and mobile

MAISON is a full-stack shopping platform I designed, built and run in production. It started as a MERN store and grew into a complete commerce system with its own brand, a native mobile app and real payments.

**What makes it different**

- **Editorial luxury design.** The storefront is styled like a fashion magazine rather than a marketplace, using Tailwind, with full light and dark themes.
- **Real payments with server-side verification.** Checkout runs through Cashfree. A webhook confirms each payment, and the backend creates the order only after the payment status checks out, so orders can't be faked from the client.
- **Layered security.** Login supports JWT and Google OAuth, with email verification and two-factor authentication. 2FA is mandatory for admin accounts.
- **AI inside the product.** Gemini condenses long review threads into short product summaries, so shoppers see the consensus at a glance.
- **Fast and searchable.** Redis caching improved performance by 85%, and Elasticsearch handles product search.
- **Beyond checkout.** The app also includes coupons, a Plus membership tier, returns and refunds, an analytics dashboard for admins, S3 media storage, and transactional email through Resend.
- **Safe one-click demo (rolling out).** Visitors can explore the full app from a shared account. Guardrails enforced on the server block payments, orders and account changes for that account.
- **Shipped like a real product.** It runs in Docker on Render at its own domain.

### [`@limiter/core`](https://github.com/AnantDuhan/limiter-core) &nbsp;![status](https://img.shields.io/badge/status-in%20progress-yellow?style=flat-square)

A production-grade, distributed rate limiter for Node.js — because every team ends up rebuilding one in-house.

- Token Bucket and Sliding Window strategies with configurable burst
- In-memory backend for development, Redis backend for distributed production
- Same API across backends, so dev → prod is a config change
- Clock-skew handling and `Retry-After` calculation built in
- TypeScript-first, with Express and Fastify adapters on the roadmap
